## 설명과 화면 연결

미노피아는 사무실 전체 → 요청·스킬 접수 → 기획 확인·내 차례 → 담당 AI → 휴대폰 대화 순서입니다. 업무 보드 이미지는 기획 승인과 상태 구분을 보여주며 결과 검토·최종 승인 화면으로 취급하지 않습니다. 기획·올리기·배포의 승인 흐름은 원본 문서를 근거로 구현 범위에 설명하고, 실제 계정·AI·클라우드 실행을 이번에 검증하지 않았음을 유지합니다.

미니어리는 PC 달력 → 날짜 확인·등록 → 프리셋 → 할 일 → 휴대폰 달력 순서입니다. 입력 중 제목·날짜·시간·메모를 보존하는 기준과, 할 일을 복제하지 않고 날짜를 옮기는 판단을 기존 기록에서 정리했습니다. 캡처는 서로 다른 날짜의 예시 화면이며 한 번의 입력으로 이어서 촬영한 세션이나 실제 동기화 결과로 주장하지 않습니다.

기능의 판단 근거에서 해당 원본 개발일지로 직접 이동합니다. 연결된 기록이 해당 프로젝트에 실제로 있을 때만 링크를 표시합니다. 제작 과정은 두 프로젝트 각각 두 사례로 정리했고, 과거 확인 결과를 이번 앱 시험 결과처럼 쓰지 않았습니다. 공개 자료의 근거 URL은 이번에 읽은 커밋으로 고정했습니다.

## 보존과 검증 경계

프로젝트 ID·개발일지·프롬프트·관리자 지정 순서·사용자 편집·JSON 백업은 변경하지 않았습니다. 새 작업 기록은 작성하지 않았습니다. 커스텀 이미지와 대표 이미지 지정은 기존 해석 순서를 유지합니다. 두 외부 포트폴리오의 새 탭 이동도 유지합니다.

확대 버튼은 이미지 로딩 중에도 창을 열 수 있게 했습니다. 확대 창의 기존 로딩·실패 안내를 사용하며, 이미지가 늦게 도착하는 상태를 실제 네트워크 응답 지연으로 만들어 320/1440px에서 열기·로드 완료·Esc·초점 복귀를 확인했습니다. 이미지가 완전히 실패한 뒤에는 기존의 실패 상태를 유지합니다.
