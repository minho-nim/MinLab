# MinLab 아카이브와 개별 프로젝트

MinLab은 프로젝트 소개·개발일지·프롬프트를 보관하고, 개별 앱은 별도 저장소와 배포 주소로 관리합니다.

## 프로젝트 목록

`archive.config.json`의 `projects`에서 프로젝트 ID, 저장소, 이름, 간단한 설명, 앱 주소를 관리합니다. 공개용 설명만 입력하세요. 목록을 갱신할 때 `version`을 올리면 새 프로젝트를 한 번 추가합니다. 기존 개인 기록은 보존하며, 사용자가 삭제한 항목을 같은 버전에서 다시 추가하지 않습니다.

카드에서는 간단한 설명과 미리보기를 제공합니다. 프로젝트 열기는 고유 주소 `#/projects/프로젝트ID`로 이동하며, 아카이브 복귀·개발일지·관리 링크를 제공합니다. 개별 앱은 새 탭으로 열 수도 있습니다.

독립 배포한 앱 자체에서 돌아오려면 해당 앱에 다음 링크를 추가합니다. 두 번째 링크의 ID는 대상 프로젝트에 맞춥니다.

```html
<a href="https://minho-nim.github.io/MinLab/">MinLab 아카이브</a>
<a href="https://minho-nim.github.io/MinLab/#/development-log?project=proj-1792563333333">개발일지</a>
```

## Codex 기록 → MinLab

1. 사용자가 개발일지 업데이트를 요청하면 Codex가 `.minlab/records.json`에 지정한 범위의 작업과 실제 요청 원문을 작성합니다.
2. MinLab `main`에 반영하면 Pages 빌드가 게시 데이터를 생성합니다.
3. 개발일지와 사용한 프롬프트 목록에서 바로 확인합니다. 별도의 초안이나 검토·저장 단계는 없습니다.

[상세 형식과 Codex 작업 규칙](./codex-records.md)을 참고하세요. 이 저장소의 `AGENTS.md`가 이후 작업에서도 기록 작성을 안내합니다.

Gemini API 키, 별도 AI 서버, 주기적 커밋 수집은 필요 없습니다. Codex가 작성한 로컬 파일만 변환하며 GitHub 커밋·다른 대화에서 내용을 추측하지 않습니다. 업로드하지 않은 로컬 기록은 배포 사이트에 나타나지 않습니다.

`recordsSince`는 기존 작성분을 소급 생성하지 않기 위한 시작점입니다. 기존 기준인 2026-10-23 09:37 KST를 유지합니다. 예전 커밋 나열 초안은 새 파일에 포함하지 않으며, 기존에 저장한 수동 기록·백업은 바꾸지 않습니다.

## 공개 범위와 개인 기록

중앙 기록 파일과 게시 데이터는 GitHub Pages에 공개됩니다. Codex는 사용자 요청 중 공개 가능한 원문만 기록하며 비밀키·민감정보는 포함하지 않습니다. 비공개 저장소의 코드·커밋을 수집하지 않습니다. 원본과 출처는 파일에 보관하며 화면에는 링크를 표시하지 않습니다.

게시 기록은 목록에 직접 연결됩니다. 중복 추가를 피하고 브라우저에서 직접 수정한 내용과 삭제는 유지합니다. 브라우저의 변경이 자동으로 GitHub에 올라가지는 않습니다. 다른 PC로 이전하거나 장기 보관할 때는 JSON 백업·복원을 사용하세요.
