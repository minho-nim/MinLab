# MinFolder Windows

MinFolder를 Windows 설치형 앱으로 실행하는 별도 진입점입니다. 기존 GitHub Pages 버전은 유지하며 작업 일정 앱은 변경하지 않습니다.

## 사용 흐름

1. 기준 폴더를 선택합니다. 다음 실행에서는 마지막 경로를 다시 연결합니다.
2. 원본과 같은 가로 폴더 지도에서 `+`로 하위 폴더를 펼치고, 폴더 이름을 눌러 아래 파일 목록을 확인합니다. 휠로 확대·축소하고 휠 버튼을 누른 채 끌어 지도를 이동합니다. 900px 이상인 Windows 창에서는 화면 전체가 고정됩니다. 아래 파일 목록과 이동 승인 영역을 나란히 표시하고 승인 버튼을 항상 보이게 유지합니다. 큰 지도와 긴 목록은 각 영역 안에서 탐색하며, 브라우저의 좁은 화면에서는 세로로 배치합니다.
3. 파일명을 클릭하면 Windows 기본 프로그램으로 엽니다. `폴더 열기`는 탐색기로 해당 위치를 엽니다. Office, 한글, PDF, 텍스트, 이미지와 일부 미디어·ZIP을 지원하며 실행 파일·스크립트·바로가기는 앱에서 실행하지 않습니다.
4. 파일 옆 `분류` 또는 선택 후 `선택 파일 추천`으로 파일명에 맞는 목적지를 추천받습니다. 파일을 폴더 상자로 끌어도 목적지를 지정할 수 있습니다.
5. 탐색기에서 파일을 폴더 상자나 파일 분류 영역으로 놓으면 **복사 대신 실제 이동**할 항목으로 추가됩니다. 파일 선택 버튼으로 추가할 수도 있습니다.
6. 추천·지정 경로를 확인하고 `선택 파일 이동 승인`을 누릅니다. 최종 확인에서 취소하면 이동하지 않습니다.

같은 이름의 파일·폴더는 덮어쓰지 않습니다. 실패한 항목은 대기 목록에 남습니다. 원본이 바뀌면 새로고침 후 다시 추가하고, 목적지가 바뀌면 다시 선택하세요. 이동 기록은 로컬에 최근 100건 저장하며 화면에는 최근 30건을 표시합니다. 자동 되돌리기는 이 버전에 포함하지 않습니다.

## 탐색과 추천

- 시작 시 기준 폴더 한 페이지와 처음 16개 상위 폴더의 한 페이지만 읽습니다. 모든 하위 폴더를 재귀적으로 읽지 않습니다.
- 폴더는 요청당 최대 100개 항목을 읽습니다. `다음 항목 보기`로 이어서 읽습니다. 화면의 트리 표시는 최대 450개 노드로 제한합니다.
- 읽은 폴더는 실행 중 메모리에서 재사용합니다. 디스크에 전체 폴더 지도를 저장하거나 실시간 파일 시스템 감시를 수행하지 않습니다. 외부 변경은 `선택 폴더 새로고침`으로 반영합니다.
- 검색은 이미 불러온 폴더·파일 이름만 대상으로 합니다. 파일 이름은 지도에서 `파일도 보기`를 켰을 때 검색합니다. Everything처럼 드라이브 전체 인덱스를 만들지 않습니다.
- `../core.js`의 기존 파일명 규칙을 재사용합니다. `계약별공사자료 → 계약·팀 → 문서 종류`와 공통 회계·총괄장 폴더를 매칭합니다. 관련 가지를 추가로 읽되 한 가지당 최대 5페이지로 제한하고, 모호하거나 범위가 불완전하면 직접 선택하도록 합니다.
- 파일 내용은 추천에 사용하지 않습니다. 내용을 읽는 경우는 다른 드라이브로 실제 이동하며 복사 내용을 확인할 때입니다.

## 파일 처리와 공유폴더

폴더 경로·파일명·이동 기록을 외부 서버로 전송하지 않습니다. Windows에 로그인한 계정의 권한을 사용하며 SMB 암호나 별도 회사 계정을 저장하지 않습니다. 네트워크 공유는 Windows에서 접근 가능한 경로를 폴더 선택기로 지정합니다. 회사의 프로그램 실행·DLP·공유폴더 정책을 우회하지 않습니다.

같은 볼륨에서는 Windows의 덮어쓰기 없는 이동을 사용합니다. 다른 볼륨에서는 새 파일을 생성하고 내용을 복사·동기화·검증한 뒤 원본을 삭제합니다. Windows에서는 덮어쓰기를 금지한 네이티브 복사로 파일 속성과 추가 데이터 스트림도 보존합니다. 검증·삭제 단계에서는 원본·복사본의 동시 쓰기와 삭제를 제한하고, 추가 스트림의 내용까지 비교한 뒤 검증한 원본 핸들로 삭제를 요청합니다. 사용 중인 파일이나 SMB 서버가 해당 동작을 지원하지 않으면 원본을 유지하고 오류를 표시합니다. 중단 시 목적지에 복사본이 남을 수 있으며 메시지에서 확인을 안내합니다. 이동 전 원본·목적지의 파일 ID를 다시 확인하고 연결 폴더·재분석 지점은 제외합니다.

공유폴더의 이동은 다른 사용자에게도 영향을 줍니다. 실제 회사 환경의 권한, 파일 잠금, 서버 성능 및 복구 정책은 별도의 테스트 폴더에서 검증해야 합니다. 현재 Windows 실기기·회사 SMB 서버에서의 수동 검증은 완료하지 않았습니다. 이동 기록에는 경로가 남으며 `기록 지우기`로 현재 기준 폴더의 기록을 삭제할 수 있습니다.

## Windows 개발 및 설치 파일 생성

필요 환경: Node.js 22 이상, Rust stable, Visual Studio Build Tools의 C++ 데스크톱 개발 도구와 Windows SDK, Microsoft Edge WebView2. 자세한 준비는 [Tauri Windows prerequisites](https://v2.tauri.app/start/prerequisites/#windows)를 참고하세요.

저장소 루트에서:

```powershell
npm ci --prefix apps/minfolder/desktop
npm --prefix apps/minfolder/desktop run desktop:dev
npm --prefix apps/minfolder/desktop run desktop:pack
```

위 명령은 로컬 시험용 설치 파일을 만듭니다. 배포용은 `TAURI_SIGNING_PRIVATE_KEY`와 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`를 설정한 뒤 `desktop:build`를 실행합니다. 설치 파일은 `apps/minfolder/src-tauri/target/release/bundle/nsis/`에 생성됩니다. 코드 서명은 설정하지 않았습니다. 회사 정책상 서명된 앱만 허용한다면 배포 전에 조직의 서명·승인 절차가 필요합니다.

`.github/workflows/minfolder-desktop.yml`은 PR 또는 수동 실행에서 화면 검사, Windows 파일 처리 테스트와 NSIS 빌드를 실행하고 설치 파일을 Actions 아티팩트로 남깁니다. 공개 사이트를 배포하거나 GitHub Release를 게시하지 않습니다.

## 검증

```powershell
npm --prefix apps/minfolder/desktop test
npm --prefix apps/minfolder/desktop run build
npx --prefix apps/minfolder/desktop playwright install chromium
npm --prefix apps/minfolder/desktop run test:browser
cargo test --manifest-path apps/minfolder/src-tauri/Cargo.toml --lib
```

GUI 라이브러리가 없는 환경에서는 `cargo test --manifest-path apps/minfolder/src-tauri/Cargo.toml --no-default-features --lib`로 파일 처리만 검사할 수 있습니다. 브라우저 검사는 Tauri 호출을 대체한 화면 통합 검사이며, Windows 기본 프로그램 실행·탐색기의 실제 OS 드롭·SMB 성능 검증을 대신하지 않습니다. 시스템 Chromium을 쓰려면 `CHROMIUM_PATH`를 지정합니다.

### 화면 비교와 반응형 검사

`npm --prefix apps/minfolder/desktop run test:ui`는 320·400·768·1024·1400px에서 빈 화면·긴 파일명, 키보드 열기, 지도 확대·이동과 권한 오류·로딩 상태를 검사합니다. `npm --prefix apps/minfolder/desktop run capture:ui`는 같은 예시 폴더로 현재 화면을 촬영합니다. 촬영 파일은 기본적으로 OS 임시 폴더의 `minfolder-ui`에 저장하고 `MINFOLDER_CAPTURE_DIR`로 바꿀 수 있습니다. 스크린샷은 저장소에 커밋하지 않습니다.

화면은 minoffia-skills의 `frontend-ui-engineering`과 `ui-check`를 참고해 기존 녹색·종이색과 가로 지도를 유지하고, 상단 안내 높이와 작업 영역 배치를 다듬었습니다. 예시 데이터 기반 브라우저 촬영이며 실제 Windows 창의 스크린샷은 아닙니다.

## 미니어리 방식의 창과 자동 업데이트

상단 왼쪽은 닫기·최소화·최대화/복원이며 빈 제목 영역을 끌어 창을 이동합니다. 앱은 한 인스턴스만 실행하고 다시 켜면 기존 창을 보여 줍니다. 처음에는 최대화하며 최소 창 크기는 900×600입니다. 버전 버튼은 `V.0.1.0` 형식으로 표시하고 클릭하면 업데이트 상태와 자동 확인·다운로드 설정을 엽니다.

실행 10초 후와 4시간마다 GitHub의 MinFolder 전용 버전 정보를 확인합니다. 자동 확인·다운로드를 끌 수 있습니다. 파일명·경로·내용을 보내지 않으며 버전 정보와 설치 파일만 요청합니다. 다운로드 후 Tauri 서명과 서명에 포함된 버전을 검증합니다. 사용자가 **설치 후 재시작**을 눌러야 적용합니다. 이동 중이거나 아직 처리하지 않은 분류가 남으면 설치를 막고, 네이티브 파일 작업 잠금을 확보한 뒤 새 이동을 차단하고 설치합니다. 실패 시 잠금을 풀고 다시 시도하도록 합니다. 종료 시 미처리 분류가 있으면 확인하며 원본 파일은 건드리지 않습니다.

업데이트의 암호 서명은 Windows의 Authenticode 게시자 인증서와 별개입니다. 설치 파일은 여전히 게시자 인증서가 없으며 회사 정책에 따라 제한될 수 있습니다. 실제 다음 버전으로의 교체와 회사 SMB 환경은 후속 실기기 검증이 필요합니다.

### 후속 버전 배포

1. `desktop/package.json`·해당 lock·`src-tauri/Cargo.toml`·`tauri.conf.json`의 버전을 함께 올리고 릴리스 노트를 갱신합니다.
2. 최초 한 번 저장소 Actions Secret `MINFOLDER_UPDATER_PRIVATE_KEY`에 기존 **비공개 서명 키 파일의 전체 내용**을 등록합니다. 키를 공개 저장소·릴리스·채팅에 올리지 않습니다. 공개 키는 앱 설정에 포함되므로 비공개 키를 재생성하거나 바꾸지 않습니다.
3. 변경을 main에 반영한 뒤 Actions의 **MinFolder Windows 앱 배포**를 실행합니다. main만 허용하며 검사·Windows 파일 처리·실제 네이티브 창 시작을 통과한 뒤 설치 파일과 서명을 생성·검증합니다.
4. `minfolder-v0.1.0` 같은 버전별 릴리스에는 `MinFolder-Setup.exe`, `.sig`, `latest.json`, `SHA256SUMS`를 공개합니다. 기존 버전은 덮어쓰지 않습니다. MinLab의 다른 앱 최신 릴리스를 바꾸지 않습니다.
5. MinFolder 전용 `minfolder-updates` 릴리스의 `latest.json`만 갱신합니다. 앱은 이 고정 주소를 확인하고 서명된 버전별 설치 파일을 받습니다.

현재 연결 도구는 저장소 Secrets API 접근이 403으로 거부되어 이 Secret을 대신 등록하지 못합니다. 최초 설치 파일은 로컬에서 기존 비공개 키로 서명해 만들 수 있으며, 후속 배포 워크플로 자동 서명에는 소유자의 1회 Secret 등록이 필요합니다. Secret은 키 파일을 안전하게 보관한 소유자가 직접 등록합니다.

로컬에서 직접 서명할 때는 `tauri signer sign --private-key-path <비공개키> --app-version <앱버전> <설치파일>`을 사용합니다. `verify_update` 예제로 앱에 들어간 공개 키와 서명·버전을 확인하고 `scripts/create-release.mjs`로 배포 파일과 체크섬을 만듭니다. 비공개 키는 배포 파일에 포함하지 않습니다.

단일 화면 검사는 900×600·1024×650·1280×720·1366×768·1440×900·1920×1080에서 긴 파일 목록과 분류 3건을 넣고 화면 전체 세로 스크롤이 없으며 승인 버튼이 창 안에 남는지 확인합니다. 자동 업데이트는 확인·다운로드·명시적 설치, 잘못된 서명, 이동 중 설치 차단과 실패 후 잠금 해제를 검사합니다.
