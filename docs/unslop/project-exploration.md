# 프로젝트 탐색 개선

사용자가 제안 세 가지를 모두 진행하도록 요청한 범위다. 기존 차콜·세이지, 한국어 문구, 실제 이미지와 데이터, 공개/관리 화면 구분은 유지한다.

## 모바일 대표 화면

899px 이하에서는 실제 프로젝트 화면을 하나 크게 표시하고 아래 가로 썸네일에서 선택한다. 이름과 분야, 상세 이동을 함께 표시한다. 선택 버튼은 누름 상태를 알리고, 방향키·Home·End로도 이동한다. 버튼 선택은 홈 안의 미리보기만 바꾸며 주소나 세로 스크롤을 강제로 변경하지 않는다. 데스크톱의 비대칭 화면 모음과 커서 반응은 유지한다. 이미지가 없는 프로젝트를 실제 화면처럼 꾸미지 않는다.

## 대표작 선택 기준

`selectHomeProjects`는 원본 배열·프로젝트를 변경하지 않는 화면용 선택이다.

1. 숨김·보관 항목은 홈 대표작에서 제외한다. 전체 아카이브의 기존 순서와 접근 가능 여부는 바꾸지 않는다.
2. 실제 화면 또는 등록된 실행 URL이 있는 프로젝트를 후보로 삼는다.
3. 첫 작품은 실제 화면이 있는 작품을 우선한다.
4. 다음에는 첫 작품과 다른 종류인 앱/게임을 배치하며, 실제 화면이 있으면 우선한다. 게임 여부는 기존 분야의 ‘게임’ 또는 ‘game’ 표기만 사용한다.
5. 그다음은 등록된 분야가 겹치지 않는 작품을 저장 순서대로 고르고, 자리가 남으면 기존 순서로 채운다.
6. 홈 화면 모음은 실제 화면 후보 중 최대 4개, 아래 대표작 탐색은 최대 6개다. 나머지 작품은 전체 아카이브에서 탐색한다.

성과·인기·완성도 등 확인되지 않은 평가로 순위를 만들지 않는다. 같은 조건에서는 관리자가 정한 저장 순서가 기준이다.

## 상세 페이지

화면만 있는 장면에는 강제 vh 최소 높이를 두지 않고, 짧은 설명은 짧은 구간, 긴 설명은 더 긴 읽기 구간을 사용한다. 긴 본문은 자르지 않고 내용에 따라 늘어난다. 같은 화면 제목을 캡션으로 중복 표시하지 않는다.

스크롤 위치에서 읽고 있는 장면을 선택하고, 기능을 직접 선택하면 해당 장면이 읽는 위치에 올 때까지 선택을 유지한다. 휠·터치·키보드로 사용자가 다시 스크롤하면 직접 선택 유지가 해제된다. 휠과 세로 스크롤은 가로채지 않는다. 모바일의 고정 미리보기 아래에서 설명을 읽을 수 있게 정렬한다.

검증 과정에서 상단 메뉴가 숨겨진 상태에서는 플로팅 메뉴를 사용하도록 확인했고, 숨긴 상단 메뉴는 inert와 aria-hidden으로 키보드/보조기술 탐색에서도 제외한다.

## 검증

- 대표작 선택의 앱/게임·분야 구성, 숨김·보관·화면 없음 처리, 중복 방지와 원본 순서 보존 자동 검사를 추가했다.
- 기존 브라우저 검증에는 모바일 썸네일 선택, 상세 URL 유지, 큰 미리보기 폭, 방향키/Home/End 선택 검사를 추가했다.
- 원본 데이터·프로젝트 ID·개발일지·프롬프트·JSON 저장 형식은 수정하지 않는다.
