# MinLab 아카이브와 개별 프로젝트

MinLab은 프로젝트 목록·개발일지·프롬프트 보관을 맡고 각 앱은 별도 저장소와 배포 주소로 관리합니다.

- `minho-nim/MinLab`: 아카이브와 기록 수집 워크플로
- `minho-nim/ChoicePilot`: ChoicePilot 앱
- `minho-nim/NutriFit`: NutriFit 앱 (비공개 저장소)

## 프로젝트 목록

`archive.config.json`에서 저장소, 이름, 간단한 설명, 앱 주소를 관리합니다. 공개용 설명만 입력하세요. 신규 브라우저에 이 목록이 등록되며 기존 개인 기록은 덮어쓰지 않습니다. 목록을 갱신할 때 `version`을 올리면 새 프로젝트를 한 번 추가합니다. 사용자가 수정·삭제한 데이터는 같은 버전에서 다시 추가하지 않습니다.

카드의 미리보기는 간단히 앱을 확인하는 창이고, 프로젝트 열기는 고유 주소 `#/projects/프로젝트ID`로 이동합니다. 프로젝트 화면은 앱과 설명만 표시하고 아카이브 복귀·개발일지 링크를 제공합니다. 프로젝트 관리는 이전 기능 편집 화면으로 연결됩니다. 개별 앱의 전체 화면은 새 탭 열기로 실행할 수 있습니다.

독립 배포한 앱 자체에도 아래 링크를 추가하면 새 탭으로 앱을 연 경우에도 돌아올 수 있습니다.

```html
<a href="https://minho-nim.github.io/MinLab/">MinLab 아카이브</a>
<a href="https://minho-nim.github.io/MinLab/#/development-log?project=proj-1792563333333">개발일지</a>
```

두 번째 링크의 프로젝트 ID는 해당 앱의 ID로 바꿉니다. 다른 사이트의 헤더를 MinLab에서 원격으로 삽입할 수는 없습니다.

## GitHub 커밋·PR → AI 초안

1. MinLab 저장소의 **Settings → Secrets and variables → Actions → New repository secret**에서 `GEMINI_API_KEY`를 등록합니다. 키는 저장소 파일이나 브라우저에 넣지 않습니다.
2. 필요하면 Actions Variables에 `GEMINI_MODEL`을 등록합니다. 기본값은 `gemini-3.8-flash`입니다.
3. **Actions → Collect GitHub record drafts → Run workflow**를 실행합니다.
4. 수집은 이후 6시간마다 실행됩니다. 최근 30일의 커밋·병합된 PR을 저장소별·한국 날짜별로 모아 하루 단위 개발일지 초안을 만듭니다.
5. MinLab 개발일지의 **GitHub 기록 초안**에서 내용을 확인하고 **검토·수정 후 저장**을 누릅니다. 새로고침은 이미 수집된 파일을 읽으며 GitHub 수집 실행 링크가 워크플로로 연결됩니다.

키가 없으면 커밋·PR 원문을 모은 초안을 생성하고 `GitHub 원문 · AI 미연결`로 표시합니다. AI 요약으로 표시하지 않습니다. Gemini 오류 시 워크플로는 실패로 표시되고 기존 배포 파일은 유지됩니다. 실제 모델 호출에는 제공자의 이용 한도·비용이 적용됩니다. 호출은 실행당 최대 8개이며 남은 항목은 다음 실행에서 요약합니다.

`syncRecords: true`인 공개 저장소만 수집합니다. 현재 비공개 NutriFit은 앱 목록에 연결하되 코드·커밋·프롬프트를 공개 초안으로 가져오지 않습니다. 비공개 기록을 자동화하려면 별도 비공개 저장소/인증된 기록 저장소를 설계해야 합니다.

생성 파일 `public/data/github-drafts.json`은 공개됩니다. GitHub 원문과 AI 결과는 작업 기록 초안이며 수집기가 실제 테스트를 실행했다고 표시하지 않습니다. 수집용 봇 커밋은 다음 수집에서 제외합니다. 생성 파일이 바뀌면 커밋 후 Pages 배포 워크플로를 명시적으로 실행합니다.

## 사용한 프롬프트

커밋만으로 실제 사용한 프롬프트를 복원할 수 없습니다. 각 공개 프로젝트에 `docs/prompt-log.example.json`과 같은 배열을 `.minlab/prompts.json`으로 저장하면 원문·날짜·결과를 가져옵니다. ID는 바꾸지 않아야 중복 저장을 피할 수 있습니다. 예시 파일은 실제 기록이 아니므로 그대로 제출하지 마세요.

프롬프트 원문에 키·개인 정보가 포함되지 않았는지 확인하고 공개 가능한 기록만 저장합니다. 프롬프트를 기록하지 않은 프로젝트에는 가상의 프롬프트를 생성하지 않습니다.

## 개인 데이터 보존

공개 초안을 검토해 저장한 기록과 수동 기록은 기존처럼 현재 브라우저에 보관됩니다. 별도로 JSON 백업을 유지하세요. 초안 저장은 개인 데이터를 GitHub로 업로드하는 기능이 아닙니다. 다른 PC에서 확정된 기록을 공유하려면 JSON 복원 또는 이후 인증된 데이터베이스 연동이 필요합니다.
