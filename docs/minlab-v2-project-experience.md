# MinLab v2 프로젝트 탐색과 상세 UX

홈은 실제 앱 화면 4개와 한국어 소개, 스크롤형 대표작 탐색, 최근 개발 기록으로 연결한다. WorthIt과 MinSnakey는 각 앱이 제공하는 샘플 모드의 실제 화면을 캡처한 WebP를 사용한다. MINOVA와 MuscleMap의 기존 화면도 유지한다. 샘플 앱 화면을 사용자의 실적이나 실제 사용 데이터로 해석하지 않는다.

## 상세 페이지

- 소개 → 기능 쇼케이스 → 실제 기록의 제작 배경 → 개발 타임라인 → 기록된 결과·다음 작업 → 프로젝트 이동 순서다.
- 쇼케이스는 스크린샷만 사용한다. 기능별 화면은 `featureId` 또는 동일한 화면 설명으로 연결하며, 연결되지 않은 화면도 별도 장면으로 볼 수 있다. 기능 설명은 있지만 연결 화면이 없는 경우 미등록 상태를 표시한다.
- 데스크톱에서 큰 화면이 고정되고 기능 설명을 충분히 읽을 수 있는 스크롤 구간을 둔다. 기능 이름, 이전/다음 버튼도 같은 장면을 선택한다. 모바일은 위 미리보기·아래 설명 구조다. 휠이나 세로 스크롤을 가로채지 않는다.
- 실제 앱은 등록된 `liveUrl`을 새 탭으로 연다. URL이 없으면 실행 버튼을 만들지 않는다. iframe과 앱 내부 재구현은 사용하지 않는다.
- 개발 기록은 실제 날짜 기준 최신순이다. 데스크톱은 왼쪽 버전 목록·오른쪽 기록, 모바일은 기록 아코디언이다. 요약과 펼쳐보는 원문을 분리하고, 버전 비교는 선택한 두 기록의 변경·이유·해결·검증·다음 작업을 나란히 보여준다. 기록이 없으면 추정하지 않는다.
- 스크린샷의 선택 필드 `version`이 실제 기록의 버전과 같으면 해당 기록과 함께 표시한다. 과거 화면이 없으면 현재 화면을 과거 버전으로 표시하지 않는다.
- 관련 프로젝트는 같은 분야, 의미 있는 공통 기술/기능, 설명의 공통 문제, 직접 지정한 ID 순으로 최대 3개다. React 등 범용 기술만 같으면 추천하지 않는다. 다음 프로젝트는 저장된 순서를 따르고 마지막은 이전 아카이브 상태로 돌아간다. 미니 탐색기는 모바일에서 접을 수 있다.

## 목록·소개·메뉴

아카이브는 Grid/List가 동일한 검색·분야·상태·태그·정렬 URL을 공유한다. 추가 필터는 기본적으로 접혀 있고 펼침 상태도 브라우저에 보관한다. List는 이름·분야·상태·실제 수정 날짜를 비교한다. 데스크톱 포인터에만 화면 미리보기를 추가한다.

About은 자기소개·성장 과정·역량 선택을 연결한다. 역량별 프로젝트는 기존 개발 기록에 실제 관련 내용이 있는 경우에만 표시하고 그 기록으로 연결한다. 경력 연차·기술 숙련도·성과 수치는 생성하지 않는다.

상단 메뉴는 아래 스크롤에 숨고 작은 플로팅 메뉴로 전환되며 위 스크롤에 복귀한다. 전체 화면 메뉴는 native dialog로 키보드·Escape를 지원한다. 모바일과 애니메이션 축소 환경에서는 동작을 줄인다. 모든 상세 이동은 기존 해시 URL을 유지한다.

## 관리자와 데이터

`#/admin`, 프로젝트 `/manage`, 개발일지 `?edit=1`은 브라우저 로컬 편집 환경이다. 인증된 서버 관리자로 설명하지 않으며 GitHub 파일이나 운영 사이트를 쓰지 않는다. 방문자 메뉴에는 편집 진입 버튼을 표시하지 않는다.

프로젝트·기록·이미지 편집과 정렬은 `minlab_content_draft_v2` 초안에 저장한다. 적용된 데이터는 기존 `minlab_projects_data_v2`에 유지한다. 변경 검토 후 명시적으로 승인해야 이 브라우저의 방문자 화면에 적용된다. 프로젝트 ID와 기록 연결을 유지하며, 삭제 전 스냅샷 복구·초안 취소·JSON 백업을 제공한다. 소개 초안도 별도로 검토하고 적용한다.

JSON 복원은 중복 ID와 구조 검증 → 추가/변경/제거 및 기록 수 확인 → 확인 → 현재 JSON 다운로드 → 초안 복원 순서다. 기존 가져오기 마이그레이션은 유지한다. 등록된 개발일지·프롬프트 원본 파일은 수정하지 않는다.

Figma 대상은 `DRa0wR6F4MyFHWqmmypro0`이며, 이번 세션에서 Starter 플랜 MCP 호출 한도에 막혀 읽기·시안 반영을 완료하지 못했다. 웹 구현으로 검토한다.
