# Codex에서 작업 기록 남기기

## 흐름

사용자의 개발일지 업데이트 요청 → `.minlab/records.json`에 지정한 범위의 개발일지·실제 프롬프트 작성 → MinLab에 커밋·업로드 → 배포 → 개발일지·프롬프트 목록에 직접 반영.

개발일지는 사용자가 별도로 업데이트를 요청할 때만 작성합니다. 코드 수정이나 대화가 끝났다는 이유로 기록하지 않습니다. 별도 AI API 키·AI 서버·주기적 수집·백그라운드 갱신은 사용하지 않습니다. 업로드가 없으면 배포 사이트의 기록도 바뀌지 않습니다. 화면에는 초안 목록, 검토·저장 버튼, 초안 새로고침, 배포 상태, 기록 원본 링크를 표시하지 않습니다.

## 기록 형식

개발일지는 ‘~함·~했음·~예정임·~필요함’ 문체를 사용합니다. 작업 주체와 대상, 날짜, 변경 내용, 수정 이유, 구현·확인 방법을 기존 항목에 나눠 담아 6하원칙을 자연스럽게 드러냅니다. 알 수 없는 주체·시각·결과는 추측하지 않습니다. 실제 프롬프트 원문은 문체 교정 대상에서 제외합니다.

한 파일의 `records` 배열에 프로젝트별 작업을 추가합니다. 아래는 형식 예시이며 실제 수행하지 않은 작업을 그대로 등록하면 안 됩니다.

```json
{
  "version": 1,
  "records": [
    {
      "id": "2026-10-23-project-preview",
      "projectId": "proj-1792485558773",
      "recordedAt": "2026-10-23T12:30:00+09:00",
      "version": "",
      "title": "프로젝트 미리보기 개선",
      "summary": "사용자 요청에 따라 Codex로 MinLab 프로젝트 미리보기 흐름을 개선함.",
      "changes": ["기록할 수 있는 실제 변경 내용만 항목별로 작성함."],
      "reason": "사용자가 보고한 문제를 해결하기 위해 개선함.",
      "testResult": "미실행: 별도 기능 테스트는 실행하지 않았음.",
      "nextSteps": "실제 사용 흐름의 추가 확인이 필요함.",
      "urls": [],
      "prompts": [
        { "id": "request-1", "title": "사용자 요청", "prompt": "실제로 사용한 요청 원문", "outcome": "이 요청에 따라 수행한 결과" }
      ]
    }
  ]
}
```

- `projectId`는 `archive.config.json`에 등록된 ID입니다. NutriFit 앱의 공개 코드 저장소와 원본 저장소는 동일한 NutriFit 프로젝트 ID로 기록합니다.
- `id`는 프로젝트 안에서 고유해야 합니다. 같은 작업을 수정할 때는 ID를 유지합니다. 같은 날짜의 다른 작업은 다른 ID로 추가합니다.
- `recordedAt`은 실제 작성 시각이며 날짜 표시는 기본적으로 한국 시간으로 계산합니다. 사용자 요청에 따라 이전 작업을 정리할 때는 `date`에 표시할 작업 날짜(YYYY-MM-DD)를 별도로 지정하고, 실제 작성·검증 시각은 유지합니다. `recordsSince`는 `recordedAt` 기준으로 적용됩니다. 요청하지 않은 과거 기록을 소급 생성하지 않습니다.
- `summary`, `changes`, `title`은 필수이며 나머지 설명은 확인한 내용만 적습니다. 검증 결과를 비우면 미실행으로 표시합니다.
- `prompts`는 선택 사항입니다. 원문을 볼 수 없거나 공개할 수 없으면 빈 배열로 두고 가상의 프롬프트로 채우지 않습니다.
- `urls`는 실제 관련 GitHub 커밋·PR 등의 링크를 선택적으로 적습니다. 첫 번째 출처는 이 중앙 기록 파일입니다.
- 기록 전체는 공개됩니다. 비공개 저장소에서 작업하더라도 중앙 파일에 넣는 내용은 사용자가 공개하기로 한 작업 설명과 안전한 요청 원문만 포함해야 합니다. 비공개 코드는 읽거나 전송하지 않습니다.

## 반영

`npm run records:sync`로 게시 데이터를 생성합니다. 개발 서버·빌드에서도 파일 변환만 실행합니다. GitHub `main`에 올라온 기록은 기존 Pages 배포에서 함께 반영되며 방문 시 일반 개발일지·프롬프트에 바로 표시됩니다. AI 호출이나 네트워크 수집은 하지 않습니다.

같은 ID의 게시 기록은 중복 추가하지 않습니다. 기존 수동 기록·사용자가 직접 수정한 필드는 보존하며, 브라우저에서 삭제한 게시 기록도 새로고침만으로 다시 생성하지 않습니다. 브라우저에서 작성·수정한 데이터는 계속 JSON 백업을 유지하세요. 원본과 관련 출처는 `.minlab/records.json` 및 Git 이력에 보관합니다. [운영 메모](./record-maintenance.md)에서 나중에 확인할 파일 위치를 안내합니다.

## 다른 Codex 프로젝트에서 사용

이 PC의 상위 `개발/AGENTS.md`가 형식과 중앙 파일 위치를 안내합니다. 다른 PC나 별도 작업 공간에서는 MinLab 저장소의 이 문서와 `AGENTS.md`를 함께 제공하세요. Codex가 접근할 수 없는 다른 채팅의 내용은 자동으로 수집되지 않습니다.
