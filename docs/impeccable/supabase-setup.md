# MinLab 서버 저장 연결

구현 대상은 Supabase Auth + Postgres입니다. 무료 요금제의 현재 한도/휴면 정책은 Supabase에서 확인하세요. GitHub Pages는 그대로 사용하며 서버 기능이 설정되지 않으면 기존 로컬 편집 모드로 동작합니다.

## 소유자가 할 초기 설정

1. 사용자 소유 Supabase 프로젝트를 만듭니다. SQL Editor에서 `supabase/migrations/202611120001_portfolio.sql`을 한 번 실행합니다.
2. Authentication → Users에서 관리자 계정을 만듭니다. 공개 회원가입은 끕니다. 관리자 이메일/비밀번호는 사이트 로그인에 직접 입력하며 채팅/GitHub 변수에 저장하지 않습니다.
3. 위 사용자의 UUID로 SQL을 실행합니다: `insert into public.portfolio_admins(user_id) values ('관리자 UUID');`. 일반 가입자는 관리자 권한이 없습니다.
4. 프로젝트의 URL과 **publishable key**를 가져옵니다. `service_role`, secret key, DB 비밀번호는 사용하지 않습니다.
5. 로컬 테스트는 `.env.local`에 `.env.example`의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 넣고 Vite를 재시작합니다. 이 파일은 커밋하지 않습니다.
6. GitHub 운영 빌드는 저장소 Settings → Secrets and variables → Actions → **Variables**에 같은 두 이름의 공개 설정을 추가합니다. 배포 워크플로가 빌드 시 읽습니다. 기존 비공개 미리보기는 같은 설정으로 다시 빌드해야 합니다. 정적 Vite 빌드에는 호스팅 런타임 변수만 바꿔도 반영되지 않습니다.
7. `#/admin`에서 로그인합니다. 기존 데이터를 서버 초안으로 저장 → 공개 전 변경 검토 → 승인하고 서버에 공개 순서로 최초 반영합니다. 빈 서버 초안을 기존 기록 위에 불러오지 마세요.
8. 다른 새 브라우저에서 공개 결과를 확인합니다. 초안·백업 테이블에 익명 접근이 안 되는지도 검증합니다.

## 동작과 권한

- 로그인 토큰은 탭의 sessionStorage에 저장하고 만료 직전 갱신합니다. 모든 실제 쓰기는 서버가 관리자 UUID를 확인합니다.
- 서버 초안/공개 데이터/백업을 분리합니다. 프로젝트 ID, 개발일지, 프롬프트, 선택 이미지 필드와 About 소개 문구를 저장합니다. 현재 UI의 다른 고정 소개 문구/메뉴 항목은 코드 설정입니다.
- 모든 쓰기는 RPC를 통합니다. RLS와 테이블 쓰기 권한 회수로 익명·일반 회원의 쓰기를 막습니다. 관리자 테이블에도 브라우저에서 권한을 추가할 수 없습니다.
- 저장/공개 시 행 잠금과 revision 비교로 다른 창의 변경 덮어쓰기를 막습니다. 충돌 시 JSON 백업 후 서버 초안을 다시 불러옵니다.
- 저장 전 이전 초안, 공개 전 이전 공개 데이터를 자동 백업합니다. 최근 20개를 UI에서 불러와 재검토할 수 있습니다. 자동 공개 복원은 하지 않습니다.
- 공개 RPC는 숨김/보관 프로젝트를 제외하고 표시 순서를 유지합니다. 초안·백업에는 원본을 보관합니다.
- 기존 이미지 업로드의 data URL/등록 URL을 보존합니다. 별도 Storage 업로드/버킷은 만들지 않습니다. 초안 본문은 15 MB, 소개 문구는 20,000자까지 서버에서 제한합니다.
- 서버 공개 데이터가 없거나 초기 조회가 실패하면 기존 정적 포트폴리오를 보여줍니다. 서버가 연결되지 않았다는 이유로 로컬 데이터를 삭제하지 않습니다.

## 현재 검증 범위

실제 서비스 프로젝트/계정은 이 저장소에 연결되어 있지 않습니다. 화면·통신 계약은 격리된 모의 API로 검증했습니다. 마이그레이션과 SQL 권한/RLS/RPC는 PGlite의 로컬 PostgreSQL 엔진과 모의 auth.uid에서 실행 검증했습니다. 실제 Supabase의 Auth·PostgREST·계정 권한·네트워크·공개 읽기 검증은 프로젝트 연결 후 완료해야 합니다. 로컬 검증 통과를 실서비스 연결 완료로 보지 않습니다.

로컬 SQL 검증을 재현하려면 임시 디렉터리에 `@electric-sql/pglite`를 설치하고 `PGLITE_MODULE=<임시 설치 경로>/node_modules/@electric-sql/pglite node scripts/test-backend-sql.cjs`를 실행합니다. 앱 런타임 의존성으로 추가하지 않았습니다.
